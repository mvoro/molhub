# AI Hub — правила для агентов

Стек: Vite + React 19 + TypeScript, Tailwind v4, shadcn/ui (стиль `radix-nova`), иконки Hugeicons
(`<HugeiconsIcon icon={XxxIcon} strokeWidth={ICON_STROKE} />`, `ICON_STROKE` из `@/lib/icons`; lucide удалён),
шрифт Geist. UI только на русском. Дев-сервер — порт 5192, Storybook — 6007
(`.claude/launch.json` → `ai-hub`, `ai-hub-storybook`).

## Публикация
- Публиковать на GitHub Pages только по отдельному явному запросу пользователя на публикацию текущих изменений.
- Обычные правки выполняются и проверяются локально. Не делать `git push` в `main` (он запускает Pages),
  не запускать deploy workflow и не публиковать через другие инструменты без такого запроса.
- Предыдущее разрешение на публикацию не распространяется на следующие правки (просьба пользователя 28.09.2026).

## Компоненты
- Интерфейс собирается только из компонентов shadcn — `src/components/ui/*`. Никаких сырых `<button>`, `<input>`,
  самодельных модалок, меню, бейджей, тогглов.
- Нужного компонента нет:
  1. найди его в shadcn через MCP (см. ниже) и поставь `npx shadcn@latest add <name>`;
  2. в shadcn такого нет — собери новый компонент в `src/components/ui/<name>.tsx` **из существующих
     shadcn-компонентов** (композиция, `cn`, `data-slot`, токены), не с нуля, и сразу напиши ему story.
- Экранные и фичевые компоненты (сайдбар, композер, диалоги конкретных сущностей) лежат в `src/components/*`
  и собираются только из `ui/*`.
- После `shadcn add` проверь импорты `from "cn"` (→ `@/lib/utils`, затем `npm uninstall cn`). Пропатченные
  `sidebar.tsx`, `dialog.tsx`, `drawer.tsx`, `sheet.tsx`, `tooltip.tsx`, `kbd.tsx`, `sonner.tsx`, `command.tsx`,
  `menubar.tsx`, `progress.tsx`, `pagination.tsx`, `carousel.tsx`, `questionnaire.tsx` через `--overwrite`
  не перезаписывать — сначала бэкап, потом перенос патчей.
- Все тексты в компонентах по-русски, включая невидимые: `sr-only`, `aria-label`, `title`, значения по умолчанию
  (у свежих shadcn-компонентов они английские — переводить сразу после `add`).
- Тосты (`ui/sonner.tsx`) сами следуют теме приложения (класс `.dark`); next-themes в проекте не используется.
- Меню действий — `AppMenu*` (`ui/app-menu.tsx`), а не голый `DropdownMenuContent`.
- Открыт максимум один поповер: клик по кнопке другого закрывает текущий и сразу открывает новый. Поэтому
  `AppMenu` не модальный по умолчанию, и `Popover` тоже (библиотечный дефолт) — `modal` им не передавать.
  Модальное меню выключает остальную страницу, и до соседней кнопки доходит только второй клик.
- Подменю (`AppMenuSub`) на телефоне открывается на месте меню, а не сбоку (сбоку ему нет места): строка
  «‹ Название» сверху возвращает назад. Название задавай пропом `title` у `AppMenuSubContent`.
- Всё кликабельное — с курсором `pointer`, без исключений. Кнопки и `role="button"` получают его глобально
  (`index.css`, `@layer base`); пункты меню, опции и строки списков (`DropdownMenuItem`, `CommandItem`,
  `SelectItem` и т.п.) — классом `cursor-pointer` в своих `ui/*`. Свой кликабельный элемент — ставь `cursor-pointer`
  явно; `cursor-default` на кликабельном запрещён. Отключённое (`disabled`, `aria-disabled`) — со стрелкой.

## Поиск компонентов и иконок — через MCP
Оба сервера подключены в `.mcp.json` (конфиги по докам ui.shadcn.com/docs/mcp и hugeicons.com/docs/integrations/mcp).
- **shadcn MCP** — перед тем как брать или собирать компонент: `search_items_in_registries` →
  `view_items_in_registries` / `get_item_examples_from_registries` → `get_add_command_for_items`.
  Всегда передавай `registries: ["@shadcn"]` — в `components.json` свои реестры не заданы, без этого поиск пустой.
- **Hugeicons MCP** — любую иконку ищи через `search_icons`, имена не угадывай. Имя `kebab-case` →
  импорт `PascalCase + Icon` из `@hugeicons/core-free-icons` (`book-open-01` → `BookOpen01Icon`);
  проверь, что иконка есть во free-наборе.

## Цвет
- Только токены (`bg-primary`, `text-muted-foreground`, …). Hex, `bg-[#…]`, палитра Tailwind (`text-purple-500`)
  запрещены. Новый цвет — токен в `:root` и `.dark` в `src/index.css`.
- **Акцентные кнопки — только primary** (`#7A3FFF`, `<Button>` с вариантом по умолчанию): отправка запроса,
  покупка и апгрейд тарифа («Улучшить»), «Создать проект», главное действие листа. Никаких чёрных, серых,
  градиентных (в том числе `--gradient-molly`) или других цветных акцентов. Primary — одно главное действие
  на экран; второстепенное — `ghost` / `secondary` / `outline`; удаление — `destructive`.
  Исключение (просьба пользователя 27.09): микрофон, отправка и стоп в композере — чёрные (`bg-foreground
  text-background`, в тёмной теме белые), константа `INK` в `chat-composer.tsx`. Цена в пилюле отправки — цветом текста,
  значок молекулы при ней — цветной логотип (`MoleculeIcon colored`), тоже просьба пользователя 27.09.
- **Тултипы — только серые**: тёмно-серый `oklch(0.37 0 0)` с белым текстом (`bg-tooltip` / `text-tooltip-foreground`,
  токен `--tooltip` одинаков в обеих темах) и только через `TooltipContent`. Primary, чёрный и другие цвета
  для тултипов не использовать.

## Модалки
- Все модалки, кроме подтверждений, — `AppSheet*` (`ui/app-sheet.tsx`): на мобилке (<768px) это нижний лист
  (vaul Drawer), на десктопе — центрированная модалка (Dialog). Один API: `AppSheet`, `AppSheetContent`,
  `AppSheetHeader`, `AppSheetTitle`, `AppSheetDescription`, `AppSheetBody`, `AppSheetFooter`, `AppSheetClose`,
  `AppSheetCloseButton`. Размеры десктопа — классами `md:*`, листа — `max-md:*`.
- `variant="fullscreen"` — только когда пользователь явно сказал «фс модалка».
- Подтверждения (удаление и т.п.) — `ConfirmDialog` (`ui/confirm-dialog.tsx`), всегда по центру.
- **Кнопки в модалках — только пилюли** (просьба пользователя 27.09): стоковый `Button` с `rounded-full`, высота 40px
  (`h-10 px-4`, в `ConfirmDialog` и футерах форм) или 44px (`h-11`, кнопка во всю ширину листа); иконочные — круглые
  (`rounded-full`, как `AppSheetCloseButton`). Квадратные `rounded-lg` и другие радиусы в модалках не используем.
  `AlertDialogAction`/`AlertDialogCancel` передают `className` в `Button` (через tailwind-merge), поэтому `rounded-full`
  у них срабатывает; свою кнопку через `asChild` собирай так же — класс на `Button`, не на дочернем элементе.
- Открытие/закрытие с клавиатуры не анимируется (`instant="keyboard"` по умолчанию); ⌘K-поиск на десктопе
  не анимируется никогда.

## Табы
- Все табы и переключатели выглядят как в Архиве (`archive-dialog.tsx`): серый трек `bg-muted` (на карточке —
  `bg-foreground/6`), `rounded-full`, внутренний отступ 4px (`p-1`); сегменты `rounded-full`, текст 14px/500;
  неактивный — `text-muted-foreground`, активный — белая пилюля `bg-background` + `text-foreground`, без тени.
  Подчёркнутые табы (`TabsList variant="line"`), табы-чипы, цветной или тёмный активный таб не используем.
- Размеров два, новый — только с согласия пользователя:
  - **M** — Архив: трек 36px везде (высота контролов приложения, как кнопка меню на мобилке; до 27.09 на
    мобилке было 40px), сегмент 28px, `px-4`; на десктопе ширина по содержимому, на мобилке во всю ширину.
    `TabsList compact` (только студии «Фото»/«Видео», просьба пользователя 27.09): на мобилке по содержимому,
    у неактивного таба только иконка, имя — в `<span>` после иконки (для скринридера остаётся). Куда ещё
    ставить `compact` — решает пользователь.
  - **L** — Аудио, «Авто | Детальный» (`music/song-form.tsx`): трек 44px, сегмент 36px, `px-3`, во всю ширину,
    сегменты делят её поровну.
- Компонент по смыслу, вид один: переключение панелей с содержимым — `Tabs` (`ui/tabs.tsx`), выбор значения
  (режим, настройка) — `Segmented` (`ui/segmented.tsx`).
- Размер M зашит в `ui/tabs.tsx` по умолчанию: `TabsList`/`TabsTrigger` ставим как есть, без классов размера,
  формы, отступов и тени (Архив и хедер студий «Фото»/«Видео» так и сделаны). С иконкой — `data-icon="inline-start"`
  на иконке, отступ с её стороны компонент сам делает на 2px меньше. Нужен другой вид — сначала к пользователю.

## Мобильная шапка
- Бургер и «Новый чат» — 36px (`size-9`), как табы M. На новом чате, в «Фото» и «Видео» кнопки «Новый чат»

## Моушен
Основа — скилл Эмиля Ковальски **`emil-design-eng`**: загружай его (Skill) перед любой анимацией или
микро-взаимодействием; при расхождении с другими источниками прав он. Анимациями занимается агент
`ai-hub-motion-designer`. Коротко:
- Сначала реши, нужна ли анимация: частые и клавиатурные действия — без неё.
- Кривые и длительности — токены из `src/index.css` (`--ease-out`, `--ease-in-out`, `--ease-drawer`,
  `--duration-*`), UI-анимации короче 300 мс, `ease-out` на вход, никакого `ease-in` и `linear` для UI.
- Анимируем только `transform` и `opacity`; не с `scale(0)` — от `scale(0.95)` + `opacity: 0`.
- Поповеры и меню растут из точки триггера (`--radix-*-transform-origin`), модалки — из центра.
- Нажатие — `scale(0.97)`; выход быстрее входа; для прерываемого UI — transitions, а не keyframes.
- `prefers-reduced-motion` обязателен.

## Тексты и Tone of Voice — как у ChatGPT
- Обращаемся на «вы» (со строчной). Никогда «ты».
- Предложение что-то создать — от «мы», первое лицо множественного числа: «Что создадим сегодня?»,
  «Чем займёмся?», «Что нарисуем?».
- Плейсхолдеры и подсказки — вежливый императив: «Спросите что-нибудь…», «Опишите картинку».
- Кнопки и пункты меню — инфинитив или существительное, глагол + объект: «Создать проект», «Удалить чат»,
  «Поделиться».
- Коротко и спокойно: без восклицательных знаков, эмодзи, канцелярита и маркетинга. Пишем «ё».
- Ошибка = что случилось + что делать («Не удалось отправить. Попробуйте ещё раз.»). Пустое состояние = что здесь
  будет + как начать. Подтверждение = «Удалить чат?» + последствия + кнопка с действием.
- Тексты промптов в идеях (голос пользователя, обращённый к модели) под правило не попадают.
- UX-скиллы: флоу и юзабилити — `design:design-critique` (первое впечатление, юзабилити, иерархия,
  консистентность), любые тексты интерфейса — `design:ux-copy` (CTA, ошибки, пустые состояния, подтверждения,
  лоадеры). Загружай их через Skill; ToV из этого раздела важнее их примеров. Ведёт агент `ai-hub-product-designer`.

## Storybook
- `npm run storybook` → http://localhost:6007 (превью `ai-hub-storybook`). Конфиг в `.storybook/`; тема —
  тумблер «Тема» в тулбаре (класс `.dark`, как в приложении); вьюпорты «Мобилка 375» и «Десктоп 1100».
- У каждого компонента `src/components/ui/<name>.tsx` есть story рядом — `<name>.stories.tsx`.
  Меняешь компонент — обнови его story в том же изменении. Новый компонент в `ui/` — сразу новая story.
  Без story компонент не считается готовым.
- Конвенция: `title: "UI/<Name>"` для shadcn, `"Проект/<Name>"` для собранных нами (AppSheet, AppMenu,
  ConfirmDialog, …); `parameters.docs.description.component` по-русски — назначение и правила использования;
  контент — реальные тексты AI Hub по ToV; иконки Hugeicons с `ICON_STROKE`; истории на варианты, размеры
  и состояния (disabled, invalid, loading, пусто). Оверлеи открыты сразу (`defaultOpen`); модальные рендерятся
  в своём iframe (`docs.story.inline: false`). Эталоны — `button.stories.tsx`, `tooltip.stories.tsx`.

## Роли · 27 сентября 2026

- Каталог, детали роли и отзыв — последовательные экраны одного `AppSheet`, без наложения модалок. В деталях и форме отзыва есть возврат назад; каталог сохраняет категорию, вкладку и прокрутку.
- В каталоге нет поиска и счётчика ролей; категории выбираются через общий `AppMenu`, как в сайдбаре. Высота пикера — 36px; на десктопе он в одной строке с табами, на мобильном — под ними во всю ширину. Описание роли открыто без аккордеонов.
- Кнопка отзыва находится только в разделе «Отзывы», похожих ролей нет. Статистика (сессии, лайки, избранное, отзывы) — без иконок, с вертикальными сепараторами между показателями.
- Иконка ролей в сайдбаре и композере — Hugeicons `SignpostIcon`.
- Статистика прокручивается внутри `AppSheetBody`. Бейдж категории закреплён с наложением на нижний край аватара; заголовок отзыва и описание стоят справа от аватара. Активная роль выделена в пикере; при открытии список прокручивается к ней.

## Мобильные исправления · 27 сентября 2026

- `AppMenu` открывается по завершению тапа; возврат фокуса на его триггер не закрывает меню. Тосты shadcn/Sonner рендерятся порталом в `body`, вне сдвига сайдбара, и закрываются нажатием на карточку; кнопки действий сохраняют своё поведение.
- Камера и галерея используют нативные поля выбора файлов. Идентификаторы файлов работают и без `crypto.randomUUID` (HTTP на телефоне); MIME восстанавливается из расширения, если браузер его не передал. Недоступные вложения выглядят отключёнными и объясняются только тостом при нажатии.
- Фото в сообщениях — превью 80×80 без подписей; клик открывает вьювер. История содержит заполненные демочаты и примеры фото, PDF, Word, видео и Markdown-артефакта, не заменяя сохранённые сообщения.
- Тарифы берутся из `data/tariffs.ts`: месячные Промо/Про/Плюс/Эксперт/Максимум, годовые Про/Эксперт/Максимум. Промо — разовый. Годовые суммы и округлённые цены за месяц сохраняются ровно из скриншотов; окно моделей использует общий каталог композера, для Промо без видео.
- Режим рассуждения Молли на мобильном открывается через нижний `SettingsSheet`, на десктопе — через меню; у кнопки остаётся иконка молнии.
- Копирование текста и ссылок — через `lib/clipboard.ts` с резервным способом для недоступного Clipboard API. Тосты при копировании не показываем: у `CopyButton` остаётся галочка и сообщение для скринридера.
